# HEADV3_0413

## Motivation

`HeadV2` repaired the biggest supervision collapse, but `headv2_x = 51.04` is still far below the dense random-fixed baseline `63.12`.

Two missing pieces remain obvious from the current evidence:

1. the head still receives no explicit local geometry signal even though the timeline is irregular
2. the best input-side oracle is boundary-dense, but the head still has no direct boundary supervision branch

## HeadV3 changes

- keep `HeadV2` core semantics
  - cost-based soft assignment
  - asymmetric `log1p(left / cell_left)` and `log1p(right / cell_right)`
- add geometry-aware modulation before the cls/reg towers
  - inputs: `fresh_mask`, `log(point_scale)`, `log(point_scale / level_scale)`, `log(cell_right / cell_left)`, symmetry ratio
  - mechanism: lightweight FiLM-style modulation with a `1x1 -> ReLU -> 1x1` geometry encoder
- add boundary auxiliary head
  - predict `startness` and `endness`
  - targets are soft boundary proximity labels built on the real irregular local cell scale
  - this is training-only in the first version; inference still uses the center-based main head
  - boundary supervision is now explicitly configured and uses `SoftBCELoss` rather than reusing focal loss

## Backbone-side extension

- the wrapper now converts `irregular_selected_positions` into tubelet-level time features before VideoMAE
- the first version injects those features into `VisionTransformerCP` through a lightweight MLP time embedding
- trainability is controlled by `custom.trainable_backbone_keywords=["time_embed"]`, so the pretrained backbone can stay frozen while the new time embedding parameters remain trainable

## Intended readout

- `HeadV3-X > HeadV2-X`:
  geometry-aware head inputs and boundary auxiliary supervision are both likely useful on the dense-like bridge path
- `HeadV3-Y > HeadV2-Y`:
  the same idea also helps the full irregular projection/neck path
- `HeadV3-TimeEmbed-X > HeadV3-X`:
  backbone-side time geometry matters beyond detector-side repair
- `HeadV3-TimeEmbed-Y > HeadV3-Y`:
  the full irregular path benefits from true backbone-side irregular awareness, not just detector-side semantics
- `HeadV3-X improves but HeadV3-Y does not`:
  head semantics keep improving, but irregular projection/neck are still the dominant bottleneck
- both fail to improve:
  the next innovation should shift from head-only repair to stronger detector reformulations, e.g. boundary-centric decoding or proposal refinement
