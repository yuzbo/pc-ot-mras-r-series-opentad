# HEADV2_0413: Irregular detector HeadV2 recovery and X/Y split

## Purpose

Check whether the new head semantics can recover the irregular detector from semantic collapse, and isolate:

1. head supervision / regression semantics
2. dense-like bridge projection + neck vs full irregular projection + neck

## HeadV2 changes

- cost-based soft assignment with top-k candidates per GT
- asymmetric `log1p(left / cell_left)` and `log1p(right / cell_right)` regression targets
- branch convs stay at `k=3`, final predictor reduced to `k=1`

## Structural interpretation

### 1. Head semantics were the dominant blocker

- `headv2_y` reaches `49.00`, which is:
  - `+9.96` over old irregular `39.04`
  - `+44.87` over `remap_no_regrange = 4.13`
- This means the HeadV2 supervision rewrite fixed the largest part of the earlier semantic failure.
- The gain is visible on both branches, so the fix is not merely overfitting to the dense-like X path.

### 2. Irregular projection + neck are not yet a net positive

- `headv2_x = 51.04`
- `headv2_y = 49.00`
- Delta: `Y - X = -2.04 mAP`

Under the same input and the same HeadV2 semantics, the only major difference is projection + neck. Therefore the current full irregular projection/FPN stack is still slightly harmful relative to the dense-like bridge path.

This does **not** mean the irregular path is hopeless. It means:

- the projection/neck branch is no longer catastrophically broken
- but it still fails to justify its extra complexity with positive accuracy gain

### 3. The main remaining gap is not explained by projection + neck alone

- dense baseline vs `headv2_x`: `63.12 - 51.04 = 12.08`
- dense baseline vs `headv2_y`: `63.12 - 49.00 = 14.12`

So the residual error budget is dominated by the broader irregular-detector formulation, not just by whether projection + neck are dense-like or irregular.

Put differently:

- HeadV2 repair explains the big jump from `4/39` to `49/51`
- projection + neck choice explains only an additional `~2 mAP`
- the remaining `12~14 mAP` gap is still structural

### 4. What this experiment now supports

- supported:
  - detector-side supervision semantics were a major bottleneck
  - HeadV2 successfully restores learnability on both X and Y
  - current irregular projection + neck are not yet better than the dense-like bridge
- not supported:
  - "once head semantics are fixed, full irregular projection/FPN will automatically beat X"

### 5. What `topk1` actually tells us

- `headv2_x = 51.04`
- `headv2_x_topk1 = 47.19`
- Delta: `topk1 - topk9 = -3.85`

This result should be read carefully:

- `topk1` here is **not** the dense ActionFormer hard assignment.
- The current head still uses the same cost-based candidate space and the same cost definition.
- What changed is mainly the support size per GT: `topk=9 -> topk=1`.

Therefore the cleanest supported statement is:

- shrinking each GT's support from multi-point to single-point hurts the current detector

What this result does **not** isolate yet:

- whether soft quality weighting itself is helpful
- whether dense-style hard assignment (`regression range + center sampling`) would be better or worse

Needed follow-up controls:

- `topk=9` with uniform weights (`1.0`) to isolate quality weighting
- a true dense-style hard-assignment bridge experiment if we want to compare against ActionFormer semantics directly
